# Videoanálise Móvel

**Mobile video analysis for physics labs.** Videoanálise Móvel is a web application for frame-by-frame video
analysis on an Android phone. Students record an experiment (a mass-spring system, a pendulum) with the phone's
camera, calibrate the scale and the axes, mark the position of each object by hand or with automatic tracking, and
export t, x, y for analysis in a spreadsheet, in Python or in the
[Laboratório de Oscilações](https://abathvictor.github.io/Physics_artifacts/laboratorio-oscilacoes/OscLab.html).

**Open it:** [abathvictor.github.io/Physics-Mobile-Track](https://abathvictor.github.io/Physics-Mobile-Track/)
(Android, Chrome). The interface is in Brazilian Portuguese.

The workflow follows [Tracker](https://physlets.org/tracker/), the free video analysis and modeling tool from Open
Source Physics, adapted to a phone screen and to a class where each student uses their own device.

## Features

- **Steps of a video analysis:** analysis interval, scale (with a magnifier on the calibration stick), axes (origin
  and angle), masses with their uncertainties, and marking.
- **Marking:** by hand, with pinch zoom, or with **automatic tracking**: template matching on each frame, a template
  that evolves slowly while anchored to the original one, and position prediction by constant acceleration or
  velocity.
- **Several objects:** up to 10 masses in the same video, plus centers of mass made of the masses the student
  chooses. Without a scale, positions are in pixels (1 px = 1 arbitrary unit, as in Tracker).
- **Graph and table:** y(t) or x(t) and a t, x, y table for the active object, kept in sync with playback and with
  the frame bar.
- **Export:** copy the table, or export CSV in Tracker's format (one or several tracks), as Excel and Google Sheets
  expect (semicolon, decimal comma) or international (comma, decimal point). Before the data, the file lists the
  masses, the units and the calibration (origin, angle and scale, as Tracker stores them).
- **Time as in Tracker:** the same Δt for every frame over the analysis interval, so a wrong timestamp in the file
  does not distort velocities.
- **Works offline:** after the first visit, the app keeps working in airplane mode and can even be reloaded without a
  connection (service worker). It can be installed from Chrome (⋮ → Install app) and opens in landscape, full screen.
- **Light and dark themes.**

For now the app works with the phone in landscape. iOS is not supported yet (decoding uses WebCodecs).

## Privacy

The video is processed on the phone and never leaves it: there is no server, no account and no data collection.
Markings are saved in the phone's browser.

## Validation

- **Synthetic videos** with known trajectories (generated by `tests/gerar_videos.py`): frame times match the file
  to within 6 µs, and automatic tracking has a maximum error of 0.4 px from 360p to 720p and 0.64 px at 1080p.
- **Comparison with Tracker** (desktop), with automatic tracking in both programs on the same real videos:
  - pendulum (1080p, 254 frames): converted back to image pixels with the calibration exported in the CSV, with no
    fitting, the trajectories differ by an almost constant offset of about 2 px (where the cursor was placed in each
    program); without that offset, they differ by 0.29 px on average (0.82 px at most). The periods are 2.1241 s
    (Tracker) and 2.1235 s;
  - two-mass oscillation (640 × 480, 667 frames): after fitting scale, rotation and origin, the trajectories differ
    by 0.12 px on average (0.54 px at most), and both programs give a period of 0.4424 s.

## Development

Plain JavaScript in native ES modules (`js/`), with no build step: edit and publish. The video is decoded with
WebCodecs, the MP4 container is read with mp4box.js, and the service worker (`sw.js`) keeps the offline copy.

To run it locally, serve the repository folder over HTTP (modules require it):

```bash
python -m http.server     # then open http://localhost:8000/
```

The tests open the app in real Google Chrome with a phone-sized screen and simulated touch. They measure synthetic
videos whose trajectories are known:

```bash
pip install -r tests/requirements.txt   # Playwright and Pillow
python tests/gerar_videos.py            # once; needs ffmpeg
python tests/test_marcacao.py           # one of the suites; HandOff.md lists them all
node tests/test_calculo.mjs             # computation, in Node, no browser
node tests/test_comentarios.mjs         # code comment standard and license lines
```

On Windows, set `PYTHONIOENCODING=utf-8`. Every function is documented with JSDoc comments in Portuguese. The
technical context, the decisions and their reasons are in [HandOff.md](HandOff.md) (in Portuguese).
